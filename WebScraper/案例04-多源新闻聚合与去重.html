一、案例背景与采集目标

前两个案例，我们一条一条地翻某一个新闻网站的列表页和详情页。可现实里的资讯需求往往不是「盯一家」，而是「盯一件事」——同一个政策、同一场发布会、同一份数据，十几家媒体都在报。只采一家，视野太窄；一家一家地采，字段对不齐、重复一大堆，最后还要花大量时间做合并。

这一案例换个思路：用订阅源（RSS / Atom）把多家媒体的更新一次性取回。订阅源是网站主动对外发布的一份标准化资讯清单，本质是一份 XML 文件，字段固定、结构统一，天然绕开了「各家页面长得都不一样」这个最大的麻烦。

1.1 这一篇用哪些真实站点

示范站点是中国新闻网（简称中新网）的 RSS 订阅中心，地址 https://www.chinanews.com.cn/rss/。打开这个页面你会看到，它把时政、财经、社会、国际、文化等多个频道各自做成一个独立的订阅地址（形如 https://www.chinanews.com.cn/rss/china.xml 这样的 .xml 文件），每个源里放着该频道最近的一批稿件。这是一个公开提供、无需登录、也没有反爬的站点，非常适合作为聚合练习的第一站。

延伸站点再配两家：36氪 https://36kr.com/feed（商业科技媒体，Atom 格式）、少数派 https://sspai.com/feed（效率工具媒体，RSS 格式）。三家格式未必一致，正好用来练后面那张「字段映射表」。

1.2 这个案例要拿到什么

  • 从 3~5 个订阅地址，各取最近的一批条目；
  • 把各家的字段映射成同一套：标题、链接、发布时间、摘要、来源媒体；
  • 把发布时间统一成同一个格式，方便排序与跨天比较；
  • 把同一件事的多家报道合并、去重，一条内容只留一次；
  • 只保留「上次采集之后」的新条目，实现增量更新。

1.3 为什么订阅源比直接采页面省事

对比项直接采页面用订阅源
页面结构每家模板不同，要分别适配XML 结构固定，一视同仁
字段位置页面改版就采空，维护成本高title / link / pubDate 是标准标签
更新判断要自己比对哪些是新的源里只放近期条目，天然增量
合规风险容易踩到反爬与授权边界网站主动公开，属于鼓励使用

可以打个比方：订阅源就像媒体给你留了一个「取件窗口」，你不用翻它的整个院子，只要按时去窗口取就行。这也解释了为什么做资讯聚合的人，第一步总是先找有没有订阅源，找不到才退回去采页面。

1.4 这个案例真正的难点在哪

采到数据不难，难在把三家的数据拼成一张干净的表。具体有三关：第一关是字段映射，RSS 和 Atom 的标签名不一样，比如发布时间一个叫 pubDate、一个叫 updated；第二关是时间对齐，中新网用的是 Tue, 08 Oct 2026 07:30:00 +0800 这种 RFC822 格式，不换算成 2026-10-08 07:30 就没法排序；第三关是跨源判重，不同媒体的链接肯定不同，但讲的可能是同一件事。这三关解决了，聚合才算真正做成。

1.5 聚合出来的表能回答什么问题

对齐、去重做完之后，这张表就不只是「一堆标题」了，它能回答很多实打实的问题：

  • 覆盖度：同一件事到底有几家媒体在报，谁报得最早；
  • 口径差异：同一份数据，财经媒体和科技媒体各挑了哪个角度；
  • 更新节奏：某个频道一天更新多少条，什么时段更新最密；
  • 线索发现：哪条资讯被多家同时选用，往往就是当天真正重要的信息。

这些问题用单家媒体都答不全，只有把多家对齐到一张表之后才看得清楚——这正是聚合的价值所在。

聚合类任务的核心不是「采」，而是「对齐」。字段对齐、时间对齐、口径对齐，三件事做完，多家数据才是一张表；做不完，就是三张表堆在一起。

2.4 中新网 RSS 的频道结构

回到示范站点 https://www.chinanews.com.cn/rss/，它的订阅入口是按频道拆开的，常用的几个是：

  • https://www.chinanews.com.cn/rss/china.xml 时政、finance.xml 财经、world.xml 国际、society.xml 社会、scroll-news.xml 即时新闻，以及文化、体育等频道；
  • 每个频道是一份独立的 XML，头部 channel 里写着频道名与简介，下面挂着该频道最近的一批 item；
  • 同一家媒体的多个频道，头部信息可以只取一次，item 逐条映射到统一字段——「一源多频道」正是订阅源最省事的地方。
映射表是聚合类任务的命根子。三家的字段名不一样，但映射到统一字段后，后面所有处理都只认统一字段，口径就稳了，换一个源也不用重写规则。

AI 助手小贴士｜RSS 与 Atom 的字段名有差别（pubDate 对 updated、link 写在属性里、作者嵌在子标签里）。让 AI 先把格式判清楚，再按映射表取字段，能少踩很多空值的坑。

打开 WorkBuddy 或任意 AI 对话工具，试试这样问：我给你的这个订阅地址可能是 RSS 也可能是 Atom。请先告诉我它属于哪一种、每条里有哪些字段（包括 guid / id、category、author），再按我给的映射表取数。

课程思政｜工匠精神与严谨求实 · 先对齐，再汇总

三份数据摆在面前，谁都能拼在一起；难的是拼完之后仍然「同一件事用同一把尺子量」。字段叫法、时间格式、空值口径，这些不起眼的细节如果不对齐，汇总出来的表看着热闹，其实一算就错。把标准写在前面，是严谨，也是效率。

五步操作主线（全课程统一，每一篇都按这个顺序推进）：

  1. 定目标与字段：先看本篇第二节的字段表，把「要哪几列、每列什么口径、要多少条」说清楚——字段清单就是验收标准，说不清就会拿回一张字段乱七八糟的表。
  2. 现场踩点（浏览器技能 BrowserSkill）：打开 https://www.chinanews.com.cn/rss/ 挑两个频道，再把 https://36kr.com/feed 一起给 WorkBuddy，说明「这是三个订阅源，格式可能不一样」。
  3. 小样试采（WorkBuddy）：先探格式不采数：让它逐个报告每个源的格式、根标签、字段清单与条数。
  4. 核对与清洗：① 三家源的字段是不是都映射到同一张表；② 每条链接能不能点开；③ 去重是按标题还是按链接（口径要写死）。
  5. 导出与归档：导出交付物（数据明细表 / 可筛选明细页 / 数据看板 / 可复用的技能包），文件名带上采集日期，并写清数据来源、采集时间与已知局限。
起手一句话（可直接复制）：用浏览器技能 BrowserSkill 打开 https://www.chinanews.com.cn/rss/（中国新闻网 RSS / 澎湃新闻 RSS），把这一页每条记录能采到的字段名和示例值列出来，先不要采集。

下面是在 WorkBuddy 里完成本案例的完整流程。你依然不写一行代码，但要负责说清标准、核对结果。

  1. 先把订阅地址收集好。打开中新网 RSS 中心 https://www.chinanews.com.cn/rss/，挑「国内新闻」「财经新闻」两个频道，再把 36氪的 https://36kr.com/feed 一并贴进对话，说明「这是三家媒体的订阅源，格式可能是 RSS 也可能是 Atom」。
  2. 要求先探格式。让它先分别打开三个源，告诉你每个源属于哪种格式、根标签是什么、里面有哪些字段、最近有多少条，先不要采数。
  3. 给出统一字段表与映射表。直接把本篇 sec2 的两张表贴进对话，让它按这张表把三家数据取成同一套字段。
  4. 先试一条源。让它只处理中新网，看看标题、链接、条目编号、时间、摘要是不是都取到了，再放开其余两家。
  5. 处理时间格式。明确要求「发布时间统一成 2026-10-08 07:30 格式，能排序，能比较早晚」。
  6. 做跨源去重。说「请先用条目编号去重，再按标题指纹找出不同来源但内容相同的条目，只保留最早发布的那一条，并在备注里写明还有哪几家也报了」。
  7. 做增量更新。把上一次的结果文件发给它，说「只新增这次比上次多出来的条目，已有的不要重复」。
  8. 导出并归档。导出成 Excel，文件名按「数据类型_日期」的约定，原始版和清洗版各留一份。
聚合任务容易「一上来就全量跑」，结果三家的时间格式乱成一团，回头排查很麻烦。先探格式、先试一条、再全量，是这里最省时间的顺序。

  - 摘要 ← description（RSS）或 summary（Atom）
  - 作者 ← author（Atom 里嵌在 author 的 name 子标签）
  - 来源媒体 ← channel 或 feed 下的 title

  - 三家结果合并成一张表
  - 先按「条目编号」去重，再按「内容指纹」找同稿多源
  - 重复的只留最早发布的一条，备注列写明「还有哪几家也报了」

6.1 五个高频问题

现象原因怎么处理

6.2 三条合规要点

  1. 订阅源是网站公开提供给人订阅的，正常读取属于作者期待的使用方式，但仍要控制频率、不要高频轮询。
  2. 只摘要与标题用于课程分析，不要把多家正文整篇搬走再发布；确需引用时注明来源与链接。
  3. 聚合不改变著作权归属。表里集齐了十家的标题，也不代表这些内容归你所有。

再补一条实操经验：合并之后，「来源媒体」这一列要一直留着。它是后面所有「哪家报得多、哪家报得早」类分析的分组依据；一旦为了让表「看起来整齐」把它删掉，这张聚合表就退化成了普通清单，也就失去了多源的意义。

遇到某个源没有订阅入口，不要转而去「硬啃」它的页面绕过限制。正确做法是换一家有公开订阅的源，或者只做原理讲解。本课的底线始终是：能公开取到的才取，取不到的不强求。

课程思政｜科技自立自强 · 把标准握在自己手里

订阅源这件事最能说明问题：谁定义了标准，谁就掌握了主动权。今天我们用别人定义好的格式取数，明天如果由我们来定义数据的字段、口径与共享方式，就能少受制于人。学会理解格式、尊重格式、乃至设计格式，正是数字时代要练的基本功。
