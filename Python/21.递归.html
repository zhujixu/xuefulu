Python 递归：函数自己叫自己

一、什么是递归

递归听着吓人，其实就是一句话：一个函数在做的过程中，又调用了它自己。

先别想数学，看一个生活例子：数一串珠子，你数到一半让同桌「帮我把剩下的数完」，同桌又让下一个人数——这就是递归的味道。

代码里长这样：

Python
12345
def f():
    print('我在干活')
    f()          # 在函数里又调用了自己

f()

它会不停地打印「我在干活」。因为 f() 里面又调 f()，永远没完——所以递归必须有个「停下来的条件」，不然就成死循环了（后面第八节会看到它怎么报错）。

递归 = 自己调自己 + 一个能停的出口。缺了出口，程序会一直往里钻，最后撞上 Python 的「递归层数上限」报错。

用循环写「倒计时」，也能得到一样的结果：

Python
1234
i = 3
while i > 0:
    print(i)
    i -= 1

输出：

输出
123
3
2
1

什么时候用递归

适合递归不适合递归
问题能拆成「和自己长得一样、但更小」的子问题简单的一次性计算
比如：阶乘、斐波那契、文件夹遍历、汉诺塔比如：加减乘除、单趟循环

起步阶段，先把「递归长什么样、怎么停」搞懂，例子都是故意挑简单的。真正复杂的递归，大二大三才用得上。

二、递归的两个必备条件

写递归函数，脑子里必须同时装两样东西，缺一个都会出错：

条件作用忘了会怎样
① 出口（基线条件）告诉函数「到这一步就别再调自己了，直接返回」永远调自己 → 层数爆掉报错
② 每步变小每次调用，问题规模都要比上一次小一点规模不变 → 永远到不了出口

用「搬砖」打比方：你搬一块，剩下的让后面的人搬（自己调自己）；但每次剩下的砖要比之前少（每步变小）；直到只剩 0 块时直接说「搬完了」（出口）。

一个合格递归的骨架

Python
123456
# 示意
def 函数(问题):
    if 问题已经小到最简单(出口):
        return 最简单答案
    把问题拆小一点
    return 函数(更小的问题)   # 自己调自己，规模更小

这是长相，不是能直接跑的代码。第三、四节用倒计时和阶乘把它变成真代码。

判断一个递归对不对，就问两句：「最最简单的那一步返回什么？」（出口）「每次是不是都比上次小？」（缩小）两句都答得上，递归就站得住。

三、第一个例子：倒计时

倒计时是最好懂的递归：从 n 数到 1。

Python
1234567
def countdown(n):
    if n <= 0:           # 出口：数到 0 或更小就停
        return
    print(n)
    countdown(n - 1)     # 自己调自己，而且 n 比上次小 1

countdown(3)

输出：

输出
123
3
2
1

走一遍：countdown(3) 打印 3，再调 countdown(2)；打印 2，调 countdown(1)；打印 1，调 countdown(0)；到 0 触发出口 return，结束。

n <= 0 是出口：告诉函数「别再往里钻了」。countdown(n - 1) 保证每次都离出口更近。两个零件齐了，递归才安全。

如果忘了出口会怎样

Python
12345
def countdown(n):
    print(n)
    countdown(n - 1)     # 没有出口！

countdown(3)

它会一直打印下去，直到 Python 受不了报错（详见第八节）。所以出口是递归的命门。

四、递归怎么走（调用栈）

递归最反直觉的是：它「一层层往里钻，再一层层往外退」。用一个调用栈来理解——每调一次，就压一层；返回时，再弹出来。

以 fact(3) 为例（阶乘函数下一节写，这里先借它看过程）：

动作栈里有什么在做的事
调 fact(3)fact(3)3 不是 1，算 3 × fact(2)，先去算 fact(2)
调 fact(2)fact(3) → fact(2)2 不是 1，算 2 × fact(1)，先去算 fact(1)
调 fact(1)fact(3) → fact(2) → fact(1)1 触发出口，返回 1
fact(1) 返回fact(3) → fact(2)fact(2) 拿到 1，算 2 × 1 = 2，返回 2
fact(2) 返回fact(3)fact(3) 拿到 2，算 3 × 2 = 6，返回 6

看出来了吗：「进去」和「出来」是反着的。先进去的最后出来（像叠盘子）。每一层都「等」着里面那层先给结果。

Python
123456
def fact(n):
    if n <= 1:
        return 1
    return n * fact(n - 1)

print(fact(3))

输出 6。这正是上面表格最后的结果。

每层递归都会占用一点内存（压栈）。递归层数太深，内存会被压满，程序就崩了——所以递归层数要有节制，别拿它去数到一百万。
记不住过程不要紧。写递归时你只管假设「里面的那次调用已经算好了」，比如写 fact(n) 时，直接相信 fact(n-1) 会返回正确答案，你只负责把它和 n 乘起来。

五、阶乘与累加

阶乘：n! = n × (n-1) × … × 1

阶乘的定义天生就是递归的：n! = n × (n-1)!，而 1! = 1 就是出口。

Python
1234567
def fact(n):
    if n <= 1:            # 出口
        return 1
    return n * fact(n - 1)   # 自己调自己，规模更小

print(fact(5))
print(fact(1))

输出：

输出
12
120
1

累加：1 + 2 + … + n

和阶乘一个套路，只是把「乘」换成「加」：

Python
123456
def sum_to(n):
    if n == 1:           # 出口
        return 1
    return n + sum_to(n - 1)

print(sum_to(5))

输出 15（也就是 5+4+3+2+1）。

阶乘和累加是「递归双件套」。它们共同说明了递归的写法：出口返回最简单情况，否则把问题拆成「当前这一步 + 更小规模的同类问题」。

递归和循环的对照

Python
12345
# 用循环写累加，更省内存
total = 0
for i in range(1, 6):
    total += i
print(total)

输出也是 15。同样的结果，循环写得也不难——这正是下一节要聊的：递归能做的，循环基本都能做。

Python
1234567
def my_max(lst):
    if len(lst) == 1:
        return lst[0]
    m = my_max(lst[1:])
    return lst[0] if lst[0] > m else m

print(my_max([3, 9, 2, 7]))

输出 9。

六、几个经典案例

1. 斐波那契数列

数列：1, 1, 2, 3, 5, 8, 13 … 规则是「每一项等于前两项之和」，开头两项都是 1。写成递归：

Python
123456
def fib(n):
    if n <= 1:           # 前两项都是出口
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))

输出 55（第 10 项是 55）。注意它同时调了自己两次，这正是它慢的原因（见第十节）。

2. 最大公约数（辗转相除法）

Python
1234567
def gcd(a, b):
    if b == 0:           # 出口：余数为 0
        return a
    return gcd(b, a % b) # 用「除数、余数」缩规模

print(gcd(12, 18))
print(gcd(7, 5))

输出 6、1。12 和 18 的最大公约数是 6；7 和 5 互质，最大公约数是 1。

3. 汉诺塔

把 n 个盘子从 A 柱移到 C 柱，每次只能挪一个，且大盘不能压小盘。递归解法是「先把上面 n-1 个挪到 B，再把最大的挪到 C，最后把 n-1 个从 B 挪到 C」：

Python
123456789
def hanoi(n, a, b, c):
    if n == 1:                  # 出口：只剩一个盘，直接挪
        print(a, '->', c)
        return
    hanoi(n - 1, a, c, b)       # 上面 n-1 个：A -> B
    print(a, '->', c)           # 最大的那个：A -> C
    hanoi(n - 1, b, a, c)       # 上面 n-1 个：B -> C

hanoi(3, 'A', 'B', 'C')

输出（每一步是「从哪根柱挪到哪根柱」）：

输出
1234567
A -> C
A -> B
C -> B
A -> C
B -> A
B -> C
A -> C

七、递归 vs 循环

老实说：前面这些递归，用循环都能写，而且循环通常更快、更省内存。

递归循环
写法短、像数学定义，好懂稍长，但要自己管计数器
速度慢（每次调用都有开销）快
内存每层都压栈，深了会爆基本不额外占内存
适合问题天然递归（树、目录、分治）绝大多数日常计算

同一个「列表求和」，循环版：

Python
12345
nums = [10, 20, 30]
total = 0
for x in nums:
    total += x
print(total)

输出 60，和递归版一模一样，但循环不用压栈、不会爆层数。

Python
1234567
def show(s):
    if not s:
        return
    print(s[0])
    show(s[1:])

show('hi')

输出：

输出
12
h
i
老师给的口诀：能用循环就别用递归。递归的价值不在「炫技」，而在那些「结构本身就是一层套一层」的问题（比如遍历文件夹、解析树）。起步阶段，递归主要用来训练拆解问题的思维。
考试/作业里让你「用递归写」时再用递归；平时自己算，优先循环。别为了递归而递归。

八、忘记出口会怎样（RecursionError）

递归如果忘了写出口（或出口永远触发不了），函数会一直调自己，层数越压越深，直到撞上 Python 的上限，抛出 RecursionError。

Python
1234
def f(n):
    return f(n - 1)     # 只有调用，没有出口

f(5)
报错
1
RecursionError: maximum recursion depth exceeded

这就是真实的报错原文：递归层数超过了上限。下面这种「规模没变小」也是同样的错：

Python
1234
def f(n):
    f(n)               # 传进去的还是 n，永远到不了出口

f(3)
报错
1
RecursionError: maximum recursion depth exceeded

两种不同的「忘出口」写法，报错都是同一句 RecursionError: maximum recursion depth exceeded。

看到 RecursionError，第一反应就是查：出口写了吗？每次调用规模真的变小了吗？十有八九是这两处漏了。循环里的死循环靠 Ctrl+C 停，递归的死循环只能改代码。
Python 默认的递归上限大约是 1000 层。你可以用 sys.setrecursionlimit() 调大，但那只是推迟崩溃，真正该做的是让递归能正常结束，而不是硬撑层数。

十、常见坑

坑 1：忘写出口 → RecursionError

Python
123
def f(n):
    return f(n - 1)   # 没出口
f(5)
报错
1
RecursionError: maximum recursion depth exceeded

每次调用都压一层栈，超过上限就崩。先写出口再写递归体。

坑 2：规模没变小，永远到不了出口

Python
123
def f(n):
    f(n)            # 传的还是 n，没缩小
f(3)
报错
1
RecursionError: maximum recursion depth exceeded

必须让参数朝出口方向靠近，比如 n - 1、lst[1:]、n // 2。

坑 3：递归里忘写 return

递归体里调了自己，却忘了 return 把结果交出来，外面拿到的是 None：

Python
1234567
def f(n):
    if n == 0:
        return 0
    else:
        f(n - 1) + 1     # 算了却没 return

print(f(3))
报错
1
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

f(n-1) + 1 算出来的结果被丢掉了，函数默认返回 None，None + 1 直接报类型错。把这一行改成 return f(n - 1) + 1 即可。

坑 4：朴素斐波那契慢得离谱

前面那个 fib(n) 每次都「双调用」，会大量重复计算。算 fib(20) 就要调自己两万多次：

Python
123456789
count = 0
def fib(n):
    global count
    count += 1
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(20), count)

输出 6765 21891——为了算第 20 项，函数被调用了 21891 次！同样的活，循环只要 20 次。所以真要算斐波那契，用循环或记住结果（记忆化），别用这个朴素递归。

递归不是「写得短就快」。像斐波那契这种「一个值被反复算」的，朴素递归是指数级变慢。大数值请用循环；如果一定要递归，也得加「缓存」避免重复算。
四个坑一句话记：出口要写、规模要小、结果要 return、别拿朴素递归算会重复的东西。

十二、递归思维小结

学了这么多例子，其实写递归就三步，记住就不慌：

步骤要想什么例子（数 1~n 的和）
① 找出口最简单到不能再小的情况返回什么n == 1 时返回 1
② 信里面假设「更小的那次调用」已经算对了相信 sum_to(n-1) 会给正确结果
③ 拼当前用这一步 + 里面的结果，凑出答案返回 n + sum_to(n-1)

用三步法写一个：数一下列表里偶数的个数

Python
1234567
def count_even(lst):
    if not lst:                 # ① 出口：空列表，偶数 0 个
        return 0
    cur = 1 if lst[0] % 2 == 0 else 0   # 当前这个数算 1 或 0
    return cur + count_even(lst[1:])     # ②+③ 当前 + 更小的列表

print(count_even([1, 2, 3, 4, 5, 6]))

输出 3（2、4、6 共三个偶数）。

新手最容易卡在哪

卡住的地方怎么破
不知道出口写什么先想「最小的输入」：空列表？n=1？长度为 1 的字符串？
不敢写「自己调自己」先假设它已经能用了，你只管把它和当前这步拼起来
写出来死循环检查每次调用的参数有没有朝出口方向变小
把「递归」当成一种思维方式而不是语法糖：先想最小情况怎么返回，再想「大问题 = 当前一小步 + 更小的问题」。能这么想，阶乘、斐波那契、汉诺塔都是同一个套路。

1下面哪句话最准确地描述了「递归」？

  • A. 一个函数自己调用自己
  • B. 函数里再调用别的函数
  • C. 把代码写在一个循环里
  • D. 函数只能被调用一次
答案：A。递归就是函数在执行过程中又调用了它自己。关键不只是调用，而是「调用的是自己」，并且要有出口让它停下来。

2一个正确的递归函数，必须同时具备哪两个条件？

  • A. 循环和列表
  • B. 出口（基线条件）和每步缩小规模
  • C. 两个参数
  • D. return 和 print
答案：B。递归两大命门：① 出口，告诉函数「到这步别再调自己了」；② 每次调用规模都比上次小，才能最终到达出口。缺一个都会无限递归。

3fact(n) 里写成 return n * fact(n - 1)，这一步主要体现了递归的哪一点？

  • A. 函数在逃避计算
  • B. 把问题拆成更小的同类问题（n 比 n-1 小）
  • C. 在给变量改名
  • D. 两个函数互相调用
答案：C。fact(n) 借助 fact(n-1) 算结果，正是「当前这一步 + 规模更小的同类问题」。配合 n<=1 的出口，递归才成立。

4递归函数忘了写出口，运行时会怎样？

  • A. 输出 0
  • B. 正常结束
  • C. 打印 None
  • D. 抛出 RecursionError
答案：D。没有出口就一直调自己，层数越压越深，超过 Python 上限就抛 RecursionError: maximum recursion depth exceeded。

5关于「递归」和「循环」，下面哪种说法更稳妥？

  • A. 递归比循环快
  • B. 循环通常更快、更省内存，能用循环就别用递归
  • C. 递归永远不会出错
  • D. 循环不能做累加
答案：B。递归每次调用都有压栈开销、层数深了会爆栈；循环基本不额外占内存。起步阶段口诀：能用循环就别用递归。

6程序运行时提示 RecursionError: maximum recursion depth exceeded，首先该查什么？

  • A. 是不是少写了 print
  • B. 是不是把变量名拼错了
  • C. 出口写没写、规模有没有缩小
  • D. 是不是没导入库
答案：C。这句报错 100% 是递归没正常结束：要么没出口，要么每次调用的规模没变小。先查这两处。

7下面哪个是递归的经典应用场景？

  • A. 汉诺塔（盘子一层套一层地挪）
  • B. 简单的 1+2+3 累加
  • C. 单次 if 判断
  • D. 打印一行文字
答案：A。汉诺塔、文件夹遍历、树结构这类「天然一层套一层」的问题最适合递归。普通累加用循环更合适。

8递归函数里调了自己却忘了写 return，外部拿到的结果通常是？

  • A. 正确的值
  • B. 0
  • C. 报错 SyntaxError
  • D. None
答案：D。没 return 的函数默认返回 None。若后面还拿它做运算，会进一步报 TypeError: ...NoneType...。记得把递归结果 return 出来。

9朴素递归版斐波那契（fib(n)=fib(n-1)+fib(n-2)）为什么慢？

  • A. 因为 Python 不支持加法
  • B. 因为大量子问题被重复计算
  • C. 因为函数名太长
  • D. 因为没用列表
答案：B。每个 fib 都要双调用，导致同样的子问题被反复算（算 fib(20) 要调两万多层）。真要算请用循环或加缓存，别用朴素递归。

10老师给的递归使用建议，最贴近下面哪句？

  • A. 所有循环都该改成递归
  • B. 能用循环就别用递归，递归留给天然递归的问题
  • C. 递归层数越多越好
  • D. 递归不需要出口
答案：B。递归主要用来训练拆解思维，和处理「结构本身一层套一层」的问题。日常计算优先循环，别为了递归而递归。
