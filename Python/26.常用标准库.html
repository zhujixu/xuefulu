一、标准库：装好就有的一整套工具

把 Python 装好，除了语言本身，还附送了几百个标准库（standard library）。它们的最大好处是：不用装、不用 pip、直接 import 就能用。

第 9 篇《导入库的方法》已经介绍过「标准库 vs 第三方库」的区别。本篇挑出五个最常用的，讲清楚它们各自解决什么问题：

模块管什么一句话记住
os文件、文件夹、路径、环境变量和老式操系统打交道
pathlib路径（更现代的写法）os.path 的升级版
json读写 JSON 格式的数据数据交换的通用格式
csv读写逗号分隔的表格文件Excel 能直接打开的纯文本表
datetime日期与时间算日期、格式化时间

为什么要专门讲这五个？因为「把数据存下来、再读回来」这件事，实际项目里天天都在做。第 24 篇《文件处理》讲的是纯文本怎么读写，本篇讲的是「数据用什么格式存、怎么存得规范」。

这一篇的量偏大，建议分两次读：先读 pathlib + json（最常用），把 csv 和 datetime 留到真正需要时再回来查。

三、json：数据交换的通用格式

要把数据存进文件，得先定一个格式。自己发明格式的问题很明显：今天用逗号分，明天想加一列就崩了。

JSON 是一个大家都认的格式：它长得像 Python 的字典和列表，几乎所有编程语言都能读写。它的规则就四条：

JSON 里的东西写法对应 Python
对象{"name": "小明"}字典 dict
数组[1, 2, 3]列表 list
字符串"abc"（必须双引号）字符串 str
数字 / 真值 / 空值12 3.5 true false null小写是 True / False / None

四、csv：Excel 能直接打开的表格

如果数据本来就是「一张表」，每行一条记录、每列一个字段，那 CSV（逗号分隔值）最合适。它的好处是：纯文本、体积小、Excel 双击就能打开、几乎所有数据分析工具都认。

一个 CSV 文件用记事本打开，长这样（三个字段、两条记录）：

姓名分数班级
小明88统计一班
小红95统计一班

它在磁盘上的原始文字其实是这样一行行的，字段之间真的就是一个英文逗号：

姓名,分数,班级小明,88,统计一班小红,95,统计一班

六、合起来用：一份会自己记日期的成绩表

把前面学的串一条线：用 pathlib 管路径、csv 存表格、datetime 记时间、json 存汇总。

Python
12345678910111213141516171819202122232425262728
# 文件：save_scores.py
import csv, json
from datetime import datetime
from pathlib import Path

def save(folder, scores):
    folder = Path(folder)
    folder.mkdir(parents=True, exist_ok=True)

    # 1) 明细存成 csv，Excel 能直接打开
    csv_path = folder / 'scores.csv'
    with open(csv_path, 'w', encoding='utf-8-sig', newline='') as fp:
        w = csv.writer(fp)
        w.writerow(['姓名', '分数'])
        w.writerows(scores)

    # 2) 汇总存成 json，带生成时间
    total = sum(s for _, s in scores)
    summary = {
        '生成时间': datetime.now().strftime('%Y-%m-%d %H:%M'),
        '人数': len(scores),
        '平均分': round(total / len(scores), 1),
    }
    json_path = folder / 'summary.json'
    json_path.write_text(
        json.dumps(summary, ensure_ascii=False, indent=2), encoding='utf-8')

    return csv_path, json_path

坑 6：json.dumps 和 json.dump 用混

Python

import json
from pathlib import Path

data = {'姓名': '小明', '分数': 88}

# dumps（带 s）= 变成字符串，返回值给你，需要自己存
text = json.dumps(data, ensure_ascii=False)
Path('a.json').write_text(text, encoding='utf-8')

with open('a.json', 'w', encoding='utf-8') as fp:

口诀：带 s 的是「转成字符串」，不带 s 的是「直接对文件操作」。其余几个也同理：loads / load。

十、常见问题

Q：os.path 和 pathlib 到底用哪个？
新写的代码用 pathlib：写法更短、跨系统更稳、有 / 可以拼路径。但老代码和老教程里全是 os.path，必须看得懂。两个混着用也可以，因为 Path() 能接字符串、str(路径) 也能变回字符串。

Q：数据存 csv 还是 json？
一句话判断：长得像一张表（每行同几个字段）→ csv；长得像一棵树（字典套列表、层层嵌套）→ json。要给人用 Excel 打开，选 csv。

Q：为什么我的 csv 用 Excel 打开中文乱码？
Excel 默认按本地编码猜。解决：写文件时用 encoding='utf-8-sig'（多了 BOM 标记，Excel 一看就知道是 UTF-8）。

Q：json.dumps 和 json.dump 我总是记混？
只记一点：带 s 的那个 s = string（字符串）。所以 dumps 返回字符串、loads 吃字符串；不带的就直接对着文件对象。四个函数按这个规律一拆就清楚。

Q：datetime.now() 每次结果都不一样，怎么测试？
这正是要小心的地方。写测试或写教程时，用固定时间 datetime(2026, 10, 4)；真实程序里用 now()。别把 now() 的结果写进需要可重复比对的输出里。

Q：这几个库要不要背？
不用。这一篇的作用是知道「有这些东西、能解决什么问题」，具体函数名忘了就查：dir(模块) 看有什么，help(函数) 看怎么用（第 25 篇《模块与包》第四节讲过）。真正需要背下来的只有「json.dumps 带 s 是转字符串」「csv 要写 newline=''」这类会踩坑的点。

1要把 'data/scores.csv' 里的文件名、后缀、所在文件夹分别取出来，下面哪个库最方便？

  • A. pathlib，用 Path(p).name / .suffix / .parent
  • B. json
  • C. csv
  • D. datetime
答案：A。pathlib 专管路径：.name 文件名、.stem 去掉后缀、.suffix 后缀、.parent 所在文件夹。它还能用 / 拼路径，自动适配 Windows 和 macOS 的分隔符。

2用 pathlib 拼出 data 文件夹下的 a.csv，写法正确的是？

  • A. Path('data') + 'a.csv'
  • B. Path('data') / 'a.csv'
  • C. Path('data').join('a.csv')
  • D. Path('data', 'a.csv', sep='/')
答案：B。Path 重载了除法运算符 / 来拼路径，这是它的标志性写法，而且会自动用对当前系统的分隔符。+ 会报类型错误，也没有 join 这个方法。

3json.dumps(data, ensure_ascii=False) 里的 ensure_ascii=False 有什么作用？

  • A. 让 JSON 能被 Excel 打开
  • B. 让 JSON 自动按字母排序
  • C. 让中文直接显示，而不是变成 \u4e2d 这样的编码
  • D. 让数据压缩得更小
答案：C。默认情况下非 ASCII 字符会被转成 \uXXXX 转义，功能没问题但人没法读。加 ensure_ascii=False 后中文原样保存——占的字节还更少。要和 Excel 打交道应该用 csv，不是 json。

4下面哪个东西不能直接转成 JSON？

  • A. 字典 {'a': 1}
  • B. 集合 {1, 2}
  • C. 列表 [1, 2]
  • D. 布尔 True
答案：B。JSON 只认「对象、数组、字符串、数字、真值、空值」。集合会报 TypeError: Object of type set is not JSON serializable，要先 list(集合) 转成列表。另外元组虽然能转，但读回来会变成列表。

5用 csv 写文件时，open() 里必须加的参数是？

  • A. encoding='gbk'
  • B. errors='ignore'
  • C. buffering=0
  • D. newline=''
答案：D。不加 newline=''，csv 自己写的换行会和 open() 的换行叠加，Windows 上每行后面多一个空行——这是 csv 最经典的坑，读和写都建议加上。

6用 csv.DictReader() 读出来的每一行是什么？

  • A. 一个列表，按列的位置取值
  • B. 一个字符串，整行原样
  • C. 一个字典，用第一行当字段名
  • D. 一个元组，不能修改
答案：C。DictReader 会拿第一行当字段名，之后每行给你一个字典，用 row['姓名'] 这种写法取值，比 row[0] 清楚得多，列顺序变了也不受影响。csv.reader() 才是返回列表的那个。

7用 csv 读进来的分数 row['分数'] 想直接参与计算，会怎样？

  • A. 它是字符串，要先 int() 或 float() 转换
  • B. 直接能算，csv 会自动转成数字
  • C. 它是分数对象，要用 .value 取值
  • D. 会报 TypeError
答案：A。csv 文件是纯文本，读进来的所有字段都是字符串，'88' 而不是 88。直接相加会得到 '88' + '95' 这种字符串拼接或者报错。先转类型再计算，和 input() 的处理一样。

8想按自定义格式显示时间，该用哪个方法？

  • A. strptime
  • B. strftime
  • C. format_time
  • D. tostring
答案：B。strftime 里的 f 是 format，把时间对象变成字符串；strptime 里的 p 是 parse，把字符串变成时间对象。两者只差一个字母，方向正好相反，是新手最容易记混的一对。

9datetime.strptime('2026/10/04', '%Y-%m-%d') 会怎样？

  • A. 正常返回 2026 年 10 月 4 日
  • B. 自动忽略符号差异，只按数字解析
  • C. 报 ValueError: time data '2026/10/04' does not match format '%Y-%m-%d'
  • D. 返回 None
答案：C。格式串里的分隔符必须和待解析的字符串一致：数据是斜杠就写 '%Y/%m/%d'，是短横就写 '%Y-%m-%d'。报错信息里会同时打出数据和格式串，照着对比就能找出差在哪里。

10算「两个日期相差几天」，正确的做法是？

  • A. 两个 date 相减，取结果的 .days
  • B. 自己拿天数除以 30 估一个
  • C. 用 date.diff()
  • D. 把年份月份日期分别相减再换算
答案：A。两个日期相减得到 timedelta，.days 就是天数。月份、闰年、跨年这些麻烦 datetime 都替你算好了，自己用 30 天一个月去估一定会错。

11关于 json.dumps 和 json.dump，说法正确的是？

  • A. 两个完全一样，随便用
  • B. 不带 s 的只能处理列表
  • C. 带 s 的用于读取，不带 s 的用于写入
  • D. 带 s 的返回字符串，不带 s 的直接对文件对象操作
答案：D。把那个 s 记成 string 就好：dumps 把对象转成 JSON 字符串（返回值给你）；dump 直接写进文件对象。loads / load 同理——一个吃字符串，一个吃文件。

12要存一份「每个学生有姓名、分数、以及多门课成绩」的嵌套数据，最合适的是？

  • A. csv，因为它是表格格式
  • B. 必须先转成集合再存
  • C. 直接写 txt，用逗号隔开
  • D. json，因为它能装字典套列表这种嵌套结构
答案：D。csv 是「一行一条、每行字段相同」的平面表，装不下「一个人对应多门课」这种嵌套。json 天生支持字典套列表，正适合这种结构。反过来，如果数据就是规规矩矩的表格、还想用 Excel 打开，那就该选 csv。
